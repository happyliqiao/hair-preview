# 微信小程序「发型 / 发色试戴」需求分析与实施计划

> 主体：企业 / 个体工商户（可注册）
> 后端：微信云开发（云函数 + 云数据库 + 云存储）
> 核心体验：**两段式** = 实时 AR 粗看（预置发型贴图 + 近似发色色罩）→ 拍照 → 云端 AI 精修高清效果图 → 保存相册 / 分享
> 使用场景：顾客扫码自助使用（理发店桌面码 / 海报码）

---

## 一、需求确认（最终版）

| 维度 | 结论 |
|---|---|
| 核心功能 | 前置摄像头画面中叠加发型 / 发色，让顾客「提前心里有数」 |
| 交互模型 | 两段式：实时 AR 粗看 → 拍照 → AI 精修 → 保存/分享 |
| 发型素材 | 预置发型库（实时段用 PNG 贴图）＋ AI 精修段用腾讯云 AI 生成 |
| 发色 | 实时段用「近似色罩」；精修段出精确发色 |
| AI 能力 | 腾讯云 / 微信 AI 能力 |
| 后端 | 微信云开发 |
| 主体 | 企业 / 个体工商户 |
| 使用方式 | 顾客自助（扫码即用，免登录优先） |
| 结果输出 | 保存到相册 + 分享（好友 / 朋友圈） |
| 支付 | 暂不涉及 |

**一句话目标**：顾客扫桌面码 → 前置摄像头实时看到自己换发型/发色的大概效果 → 满意后拍照 → 几秒内得到一张「做完这个发型+发色」的高清效果图 → 保存/分享。

---

## 二、总体方案与技术选型

### 2.1 两段式体验架构

```
顾客扫码进入
   │
   ▼
【第一段 · 实时 AR 粗看】
   camera / VKSession 取前置画面
   → 人脸检测 + 人脸 3D 网格（VKSession face 模式）
   → 叠加①预置发型 PNG 贴图（按人脸关键点对齐缩放）
   → 叠加②近似发色色罩（半透明色块罩住头发区域，粗略预览发色）
   → 顾客可左右切换发型、上下换发色，即时看到「大概方向」
   │
   ▼（顾客满意，点「生成效果图」）
【拍照】取一帧清晰画面 → 上传云存储
   │
   ▼
【第二段 · AI 精修】
   云函数调用腾讯云 AI（人脸融合 FaceFusion / 图像生成）
   → 输出「顾客脸 + 目标发型 + 目标发色」的高清效果图
   → 回显对比图（原图 vs 效果图）
   │
   ▼
【保存 / 分享】保存相册、分享好友 / 朋友圈
```

### 2.2 技术栈

| 层 | 选型 |
|---|---|
| 前端框架 | 原生小程序（或 uni-app / Taro，视团队而定） |
| 实时 AR | `wx.createVKSession`（face 模式）+ `VKFrame.getFaceMesh()` + WebGL 渲染 |
| 降级方案 | 低端机/不支持 VKSession 时 → `camera` 组件 + `wx.faceDetect`（静态人脸关键点） |
| 后端 | 微信云开发：云函数（Node.js）+ 云数据库 + 云存储 |
| AI 精修 | 腾讯云「人脸融合 FaceFusion」（推荐，模板化最可控）或 AIGC 图像生成 |
| 结果分享 | `wx.saveImageToPhotosAlbum` + `onShareAppMessage` / `onShareTimeline` + canvas 合成分享图 |

### 2.3 关于「AI 生成发型」的关键澄清

「AI 生成发型」在工程上有两种落地方式，强烈建议**先走方式 A**：

- **方式 A · 人脸融合模板化（推荐）**：预先制作/采购一批「目标发型 + 发色」的模特模板图，用腾讯云 **FaceFusion（人脸融合）** 把顾客的脸融合进模板，输出效果图。效果好、可控、单张成本低、已商用成熟。
- **方式 B · AIGC 从零生成**：用生成式模型按顾客脸型「画」出新发型。更炫但不可控（可能不像本人）、延迟高、成本高。

> 建议：第一期用「方式 A」跑通闭环，二期再评估 AIGC 生成作为进阶能力。

## 三、可行性总览（先看结论）

| 功能 | 可行性 | 难度 | 说明 |
|---|---|---|---|
| 实时 AR 叠加预置发型 | ✅ 可行 | 中 | VKSession face 模式 + 贴图对齐，正面效果好，转头/侧脸效果一般 |
| 实时近似发色色罩 | ✅ 可行 | 中 | 用粗略头发区域做半透明色罩，不做精确分割 |
| 拍照 → 云端 AI 精修 | ✅ 可行 | 中 | FaceFusion 已成熟，重点是模板制作与合规 |
| 保存相册 + 分享 | ✅ 可行 | 低 | 微信原生能力，注意授权 |
| 精确「逐帧」实时发色（头发分割） | ⚠️ 不建议第一期做 | 极高 | 需实时头发分割模型，小程序内无原生能力，低端机跑不动 |

## 四、全流程细分（第一步 → 第 N 步）

### 阶段 0：资质与账号准备（必须先做，耗时且不可压缩）

1. **注册主体**：办理企业营业执照 / 个体工商户营业执照。
2. **注册小程序**：用已有 AppID 绑定到企业主体（个人 AppID 需迁移/重新以企业主体注册小程序）。
3. **选择服务类目**：在 mp 后台选定可过审的类目（如「工具 > 图像处理」或「生活服务」类，人脸/图像处理类目审核较严，需结合最终功能确认）。
4. **注册腾讯云账号**：企业实名认证。
5. **开通腾讯云「人脸融合 FaceFusion」**：提交业务场景说明，通过审核并开通计费。
6. **开通微信云开发**：创建云开发环境（按量付费），记录环境 ID。
7. **准备合规文本**：《用户隐私政策》《用户协议》草案。

### 阶段 1：产品定义与素材准备

8. **定义 MVP 范围**：第一期发型数量（建议 10–20 款）、发色数量（建议 10–20 色）、是否免登录。
9. **设计交互流程**：扫码 → 授权摄像头 → 实时试戴 → 拍照 → AI 生成 → 对比 → 保存/分享。
10. **制作发型贴图素材**：每款发型一张「正面、透明背景 PNG」，按统一基准（头顶中心、太阳穴、鬓角锚点）规范制作。
11. **制作 AI 融合模板**：对应每款发型/发色制作 FaceFusion 模板图（需授权或自制模特图）。
12. **上传素材到云存储**：建立目录规范（`/hairstyles/xxx.png`、`/templates/xxx.jpg`）。

### 阶段 2：小程序前端开发（实时 AR 段）

13. **搭建项目骨架**：初始化小程序工程，接入云开发 SDK（`wx.cloud.init`）。
14. **摄像头能力接入**：`camera` 组件 / VKSession，处理 `scope.camera` 授权流程。
15. **人脸检测与网格**：VKSession face 模式启动，读取 `VKFrame.getFaceMesh()` 得到人脸 3D 网格。
16. **发型贴图渲染**：WebGL 中把人脸网格/关键点映射为屏幕坐标，对发型 PNG 做仿射对齐叠加。
17. **发色色罩渲染**：基于人脸尺寸/位置生成半透明色罩覆盖头发区，支持颜色切换。
18. **交互控件**：发型横向切换、发色色板切换、拍照按钮。
19. **拍照取帧**：从相机帧取清晰图 → `canvas` 合成 → `canvasToTempFilePath` 生成临时图片。
20. **降级方案**：不支持 VKSession 的机型自动切换到「静态拍照 + `wx.faceDetect` 关键点对齐」模式。

### 阶段 3：云开发后端 + AI 集成

21. **云存储上传**：`wx.cloud.uploadFile` 上传顾客照片（用后即删或短期留存，降低合规风险）。
22. **云函数 · AI 精修**：云函数内调用腾讯云 FaceFusion（携带 SecretId/SecretKey，建议用环境变量/密钥托管），入参 = 顾客照片 + 模板 ID。
23. **结果回传**：生成图存回云存储，返回 HTTPS 临时链接。
24. **云数据库**：记录发型库、发色库、模板映射关系、可选的生成历史（按需）。
25. **异步任务处理**（可选）：AI 生成耗时用「轮询 / 云函数定时 / 订阅消息」返回结果，避免前端长等待。

### 阶段 4：联调与测试

26. **真机联调**：iOS / Android 真机各至少 2–3 台（覆盖高端机与低端机）。
27. **性能测试**：实时段帧率、内存、发热；AI 段耗时与成功率。
28. **效果验收**：贴图贴合度、发色自然度、AI 精修「像不像本人」。
29. **授权流程测试**：摄像头授权、保存相册授权、拒绝授权的兜底。
30. **异常兜底**：网络失败、AI 超时、人脸未检测到、非人脸等场景提示。

### 阶段 5：合规、审核、上线

31. **配置「用户隐私保护指引」**：mp 后台声明摄像头、相册、人脸照片等信息的用途（审核硬性要求）。
32. **人脸信息合规**：敏感个人信息需单独授权弹窗 + 明确告知 + 数据最小化（用后即删）。
33. **接口权限申请**：在「开发 → 接口设置」确认 VKSession 人脸等能力是否需要申请并完成申请。
34. **提审**：提交代码审核，准备类目资质、隐私说明、功能演示视频（图像处理类目通常需要）。
35. **发布上线**：审核通过后全量发布，部署桌面码/海报物料。

### 阶段 6：上线后迭代（可选）

36. 发型/发色库扩充（远程配置，无需发版）。
37. 接入 AIGC 生成（进阶）。
38. 历史记录、收藏、会员（如未来需要，再评估支付）。

| 权限/资质 | 用途 | 类型 |

| **VKSession 人脸能力** | 实时人脸网格 | 需在「开发-接口设置」核实/申请 |
| **人脸信息单独授权** | 敏感个人信息处理 | 弹窗 + 告知 + 数据最小化 |

### 5.2 腾讯云侧

| 权限/资质 | 用途 |
|---|---|
| 腾讯云账号 + 企业实名 | 调用 AI 服务 |
| 人脸融合 FaceFusion 开通 | 需业务场景审核 |
| SecretId / SecretKey | 云函数内鉴权（建议用密钥托管/环境变量） |
| 内容安全（可选） | 图片合规过滤 |

### 5.3 合规侧

- 《用户隐私政策》+《用户协议》。
- 人脸照片存储策略：建议「生成后立即删除原图」，只保留结果图或按用户要求保存，最大限度降低合规与数据风险。
- 未成年人保护、肖像权授权提示（若涉及模板模特需授权）。

## 六、难点详解与应对

1. **实时发色的「头发分割」——最大难点**
   小程序无原生实时头发分割能力，逐帧精确抠头发在低端机不可行。**应对**：实时段只用「近似色罩」，精确发色放到 AI 精修段由 FaceFusion/图像处理完成。

2. **发型贴图的贴合度（角度/脸型差异）**
   预置 PNG 是按标准正面做的，转头、侧脸、脸型差异会导致贴图错位。**应对**：基于人脸关键点做仿射对齐 + 限定「正对摄像头」引导（画面提示「请正对屏幕」），接受正面效果为主。

3. **VKSession 平台兼容性**
   部分安卓机型 / 低版本微信不支持 VKSession。**应对**：做好能力探测，自动降级到「静态拍照 + `wx.faceDetect`」模式，保证所有用户可用。

4. **AI 精修效果可控性与模板成本**
   FaceFusion 效果取决于模板质量，需逐款制作/授权。**应对**：第一期固定少量模板，严格规范拍摄（光线、角度），把「像本人」的稳定度做上去。

5. **人脸隐私合规**
   人脸照片属敏感个人信息，审核和用户信任都是硬门槛。**应对**：单独授权弹窗 + 明确用途 + 用后即删 + 隐私指引完整披露。

6. **实时渲染性能**
   视频帧 + WebGL 叠加在低端机可能卡顿、发热。**应对**：控制纹理分辨率、做降帧/降分辨率策略、提供「性能模式」开关。

7. **审核风险**
   图像处理/人脸类目审核严格，可能多次被打回。**应对**：提前准备演示视频、资质证明、清晰的隐私说明，预留审核返工时间。
